# Electron → Tauri v2 Conversion — Design

## Goal

Replace the Electron shell with Tauri v2, keeping all existing user-facing
behavior (away message / countdown timer, background image picker, display
size presets, custom title bar, ESC-to-back) and the existing plain
HTML/CSS/JS frontend as-is wherever possible.

## Why

Electron ships a full Chromium + Node runtime per app (~150MB+). Tauri uses
the OS's native webview and a small Rust core, producing a much smaller
binary for this kind of simple single-window utility app.

## Scope

- Convert `main.js` (Electron main process) to a Tauri Rust core in
  `src-tauri/`.
- Adapt `renderer.js` and `display.js` to Tauri's JS API instead of
  `ipcRenderer`.
- Adapt `countdown.js` to work as a plain browser global (no more Node
  `require` in the renderer).
- Replace `electron` / `electron-builder` in `package.json` with
  `@tauri-apps/cli` / `@tauri-apps/api`.
- Update GitHub Actions and GitLab CI to build with Tauri instead of
  electron-builder.
- Out of scope: no new features, no frontend framework/bundler, no custom
  app icon (none exists today — use Tauri's default scaffold icon).

## Architecture

**Frontend stays in place.** `tauri.conf.json`'s `frontendDist` points at
the project root. `index.html`, `display.html`, their CSS, and their JS
stay as static files — no build step, no bundler.

**IPC surface shrinks from 4 Electron handlers to 3 Tauri commands**, because
page navigation no longer needs to go through the backend:

| Electron (`ipcMain.handle`) | Tauri equivalent |
|---|---|
| `choose-background` | `#[tauri::command] choose_background` — `tauri-plugin-dialog`, same image filter |
| `show-display(w, h)` | frontend does `location.href = 'display.html'` directly; resize/center becomes `resize_window(w, h)` |
| `show-settings` | frontend does `location.href = 'index.html'` directly; resize/center reuses `resize_window(480, 580)` |
| `quit-app` | `#[tauri::command] quit_app` — `app.exit(0)` |

Tauri serves multiple static HTML files from one webview, so swapping pages
is a normal in-page navigation — no round trip to Rust required for that
part. Only the native window resize+center stays a Rust command.

**Window config** (`tauri.conf.json`): 480×580, `decorations: false`,
`resizable: false`, background `#1e1e2e` — same as the current
`BrowserWindow` options. The custom title bar's close button calls
`quit_app` same as today.

**Renderer/JS changes:**
- `renderer.js` and `display.js` become `type="module"` scripts, importing
  `invoke` (and `convertFileSrc`) from `@tauri-apps/api/core` instead of
  `require('electron')`.
- `path.basename(filePath)` (Node) is replaced with a one-line manual
  basename extraction (split on `/`/`\`, take the last segment).
- `countdown.js` keeps its `module.exports` (for Jest) and additionally
  assigns `calculateTargetDate`/`getRemainingSeconds`/`formatTime` onto
  `window`, so it can be loaded as a plain classic `<script>` in
  `display.html` and consumed as globals from the module script — no
  bundler, no ESM conversion of the tests.

**Background image access:** the user picks an arbitrary absolute path via
the native file dialog. Tauri v2's asset protocol blocks arbitrary
filesystem paths by default. Fix: build the URL with `convertFileSrc()` and
set `app.security.assetProtocol.scope: ["**"]` in `tauri.conf.json`. This
mirrors the trust model the Electron version already had
(`nodeIntegration: true`, `contextIsolation: false`) — it's a local,
single-user desktop tool, so unrestricted local file access is an accepted
trade-off, not a regression.

**Packaging:** drop `electron` and `electron-builder` from
`package.json` devDependencies; add `@tauri-apps/cli` (dev) and
`@tauri-apps/api` (dependency). New npm scripts: `tauri dev` (replaces
`start`), `tauri build` (replaces `build`). `npm test` (Jest) is untouched —
it only exercises `countdown.js`'s pure functions.

Scaffold `src-tauri/`: `Cargo.toml`, `tauri.conf.json`, `src/main.rs`
(registers the 3 commands, sets up the dialog plugin), `build.rs`, default
icon set generated by the Tauri CLI.

## CI Changes

**GitHub Actions** (`.github/workflows/*.yml`): keep the existing 3-OS
matrix (windows-latest/macos-latest/ubuntu-latest). Add a Rust toolchain
install step and, on Ubuntu, the native webview dev packages
(`libwebkit2gtk-4.1-dev`, `libayatana-appindicator3-dev`, etc.) required to
build a Tauri app on Linux. Replace `npm run build` with `npm run tauri
build`. Update artifact glob paths to
`src-tauri/target/release/bundle/{nsis,dmg,appimage}/*`. The release job
(tag-triggered, uploads to GitHub Releases) is unchanged — it just globs
whatever the build jobs uploaded.

**GitLab CI** (`.gitlab-ci.yml`): the `build-linux` job installs Rust and
the same Linux webview dev packages in `before_script`, swaps
`npm run build` for `npm run tauri build`, and updates the artifact path to
`src-tauri/target/release/bundle/appimage/*.AppImage`.

## Testing / Verification

- `npm test` continues to pass unchanged (Jest against `countdown.js`).
- Install Rust locally (`rustup`), run `npm run tauri dev` to manually
  verify: settings window opens at 480×580, away/countdown modes both
  work, background image picker + preview work, Start Display resizes and
  centers the window and swaps to `display.html`, ESC/back button returns
  to settings, title bar close quits the app.
- Run `npm run tauri build` once to confirm a Linux bundle actually
  produces an AppImage before calling the conversion done.

## Non-goals

- No feature additions or UI changes.
- No frontend framework or bundler.
- No custom app icon.
- No changes to `countdown.js`'s logic or its test suite.
